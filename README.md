# astrbot_plugin_master_aware · 认主

> 让机器人认得「谁在跟自己说话」。

## 这解决什么问题

AstrBot 的模型**看不到发送者的 QQ 号**。所以如果你在人格里写「我的主人是 123456」，
它只是知道「存在一个主人」，并不知道**眼前这个人是不是主人**——被问到时很容易答"没有主人"或装傻。

这个插件在每次 LLM 请求前，比对发送者 QQ 与配置里的主人名单，命中就注入身份说明。

## 为什么不能只写 system prompt

最初的版本只把说明追加到 `system_prompt` 末尾，结果：

- 人设动辄几千字，说明被淹没在末尾；
- 前面几轮对话说过"我没有主人"，模型会顺着这个惯性继续答。

所以现在做两件事：

1. 追加到 `system_prompt`（长期设定）；
2. 把提示**贴到当前用户消息前面**：`【本条消息来自你的主人 123456】`。

模型对当前输入的注意力远高于几千字提示的末尾，第二条往往才是真正起作用的那个。

## 安装

插件市场搜索「认主」安装，或：

```bash
cd AstrBot/data/plugins
git clone https://github.com/QuanWander/astrbot_plugin_master_aware
```

安装后在 **WebUI → 插件 → 认主 → 配置** 里填写主人 QQ 号，重启 AstrBot。

## 配置

| 字段           | 类型     | 说明                          |
| ------------ | ------ | --------------------------- |
| `master_qq`  | list   | 主人 QQ 号，可多个。留空则插件不生效        |
| `note`       | text   | 注入的身份说明，`{qq}` 会替换成发送者 QQ 号 |
| `debug_path` | string | 可选。填写后把每次注入的内容追加写入该文件，排障用   |

## 工作原理

```
消息进来
   ↓
发送者 QQ 在 master_qq 里？
   ├─ 否 → 原样交给后续流程，不做任何事
   └─ 是 → system_prompt += 身份说明
            prompt = "【本条消息来自你的主人 xxx】\n" + prompt
   ↓
交给模型
```

插件只做注入，不拦截、不改写、不发送消息，所以不会和其他插件冲突。

## 注意事项

- **它不会让机器人"记住"主人**。每次请求都是重新注入一次说明，这就是 LLM 的工作方式。
- 如果你的人格本身很强势（比如设定成"谁都不认"），可能仍会嘴硬。可以把 `note` 写得更强硬，
  或者降低人格里相互冲突的描述。
- 主人说话仍然需要 @ 或关键词才会触发唤醒，这是 AstrBot 唤醒机制决定的，与插件无关。
